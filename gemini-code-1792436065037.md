# SYSTEM IMPLEMENTATION SPECIFICATION & BLUEPRINT
**Target System:** Multi-Tenant School Management Engine (Nursery to Class 10)[cite: 1]
**Target Architecture:** Multi-Tenant SaaS Engine (Single Database with Row-Level Security)[cite: 1]
**Primary Tech Stack:** Next.js (App Router, TypeScript), Node.js (Server Actions / API Routes), PostgreSQL (Supabase / Prisma ORM), Tailwind CSS, shadcn/ui.

---

## 1. Problem Statement & Project Overview

Educational institutions from early childhood (Nursery/LKG/UKG) through secondary school (Classes 1–10) face severe operational fragmentation[cite: 1]. Core workflows—such as daily attendance, academic tracking, timetable management, homework assignment, and parent communication—are frequently managed across disconnected channels or physical paper logs[cite: 1].

### Core Operational Challenges
* **Excessive Administrative Burden:** Teachers spend excessive non-teaching time taking manual attendance, drafting physical progress logs, and maintaining separate record sets[cite: 1].
* **Fragmented Communication Channels:** Parents lack authorized, real-time access to child attendance, homework assignments, report cards, and official school announcements[cite: 1].
* **Rigid One-Size-Fits-All Systems:** Early childhood students (Nursery to UKG) are often forced into exam-centric systems instead of developmental milestone and activity tracking[cite: 1].
* **Security & Regulatory Compliance:** School operations require strict Role-Based Access Control (RBAC) and complete audit logs for post-publication grade or attendance adjustments[cite: 1].
* **Scalability Bottlenecks:** The solution must start as an efficient prototype with minimal seed data and scale seamlessly to hundreds of schools and thousands of concurrent users without requiring architectural rewrites[cite: 1].

## 3. Data Isolation & Role-Based Access Control (RBAC)

### Tenant Isolation Strategy
* Every single database table MUST include a `school_id` foreign key referencing the primary `School` table[cite: 1].
* Application ORM queries and database-level Row-Level Security (RLS) policies MUST execute with `WHERE school_id = context.schoolId`[cite: 1].
* Cross-tenant data leakage is a critical security violation[cite: 1].

### Permission Matrix by User Role

* **School Admin:** Full tenant configuration: academic years, classes, sections, subjects, users, permissions, calendar events, and audit logs[cite: 1].
* **Principal / Management:** Read-only visibility across school-wide attendance, academic performance, teacher workloads, and pending administrative approvals[cite: 1].
* **Teacher:** Access restricted strictly to assigned classes, sections, and subjects for attendance, homework, lesson plans, and mark entries[cite: 1].
* **Class Teacher:** Teacher permissions plus class-level overview, student follow-ups, class-wide announcements, and report card preparation[cite: 1].
* **Parent / Guardian:** View-only access restricted strictly to verified linked children (attendance, homework, marks, notices, and events)[cite: 1].
* **Student:** Class-specific view for timetables, homework assignments, learning materials, and published examination results[cite: 1].
* **Accountant / Office Staff:** Module-specific access for approved administrative tasks (Fees, Admissions, Certificates)[cite: 1].

## 5. Complete Relational Database Schema (Prisma ORM)

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

enum Role {
  SCHOOL_ADMIN
  PRINCIPAL
  TEACHER
  CLASS_TEACHER
  PARENT
  STUDENT
  ACCOUNTANT
}

enum AttendanceStatus {
  PRESENT
  ABSENT
  LATE
  HALF_DAY
  APPROVED_LEAVE
}

enum GradeLevelBand {
  EARLY_YEARS // Nursery, LKG, UKG
  PRIMARY     // Classes 1-5
  MIDDLE      // Classes 6-8
  SECONDARY   // Classes 9-10
}

model School {
  id            String         @id @default(uuid())
  name          String
  code          String         @unique
  createdAt     DateTime       @default(now())
  updatedAt     DateTime       @updatedAt
  academicYears AcademicYear[]
  users         User[]
  classes       Class[]
  students      StudentProfile[]
  teachers      TeacherProfile[]
  auditLogs     AuditLog[]
}

model User {
  id             String          @id @default(uuid())
  schoolId       String
  email          String          @unique
  passwordHash   String
  role           Role
  isActive       Boolean         @default(true)
  school         School          @relation(fields: [schoolId], references: [id])
  teacherProfile TeacherProfile?
  studentProfile StudentProfile?
  guardians      GuardianLink[]
  auditLogs      AuditLog[]

  @@index([schoolId, role])
}

model AcademicYear {
  id        String   @id @default(uuid())
  schoolId  String
  name      String   // e.g., "2026-2027"
  startDate DateTime
  endDate   DateTime
  isCurrent Boolean  @default(false)
  school    School   @relation(fields: [schoolId], references: [id])
  classes   Class[]
}

model Class {
  id             String            @id @default(uuid())
  schoolId       String
  academicYearId String
  name           String            // e.g., "Class 10"
  section        String            // e.g., "A"
  band           GradeLevelBand
  school         School            @relation(fields: [schoolId], references: [id])
  academicYear   AcademicYear      @relation(fields: [academicYearId], references: [id])
  students       StudentProfile[]
  subjectConfigs SubjectTeacherAssignment[]
  attendance     AttendanceSession[]

  @@unique([schoolId, academicYearId, name, section])
}

model StudentProfile {
  id           String             @id @default(uuid())
  schoolId     String
  userId       String             @unique
  classId      String
  rollNumber   String
  dob          DateTime
  school       School             @relation(fields: [schoolId], references: [id])
  user         User               @relation(fields: [userId], references: [id])
  class        Class              @relation(fields: [classId], references: [id])
  guardians    GuardianLink[]
  attendance   AttendanceRecord[]
  marks        MarkRecord[]

  @@index([schoolId, classId])
}

model TeacherProfile {
  id          String                     @id @default(uuid())
  schoolId    String
  userId      String                     @unique
  staffId     String
  school      School                     @relation(fields: [schoolId], references: [id])
  user        User                       @relation(fields: [userId], references: [id])
  assignments SubjectTeacherAssignment[]

  @@index([schoolId])
}

model GuardianLink {
  id        String         @id @default(uuid())
  parentId  String
  studentId String
  parent    User           @relation(fields: [parentId], references: [id])
  student   StudentProfile @relation(fields: [studentId], references: [id])

  @@unique([parentId, studentId])
}

model SubjectTeacherAssignment {
  id        String         @id @default(uuid())
  classId   String
  teacherId String
  subject   String
  class     Class          @relation(fields: [classId], references: [id])
  teacher   TeacherProfile @relation(fields: [teacherId], references: [id])
}

model AttendanceSession {
  id          String             @id @default(uuid())
  classId     String
  date        DateTime           @db.Date
  period      Int?               // Null for daily attendance, populated for period-wise
  takenById   String
  createdAt   DateTime           @default(now())
  class       Class              @relation(fields: [classId], references: [id])
  records     AttendanceRecord[]

  @@unique([classId, date, period])
}

model AttendanceRecord {
  id        String            @id @default(uuid())
  sessionId String
  studentId String
  status    AttendanceStatus
  session   AttendanceSession @relation(fields: [sessionId], references: [id])
  student   StudentProfile    @relation(fields: [studentId], references: [id])

  @@unique([sessionId, studentId])
}

model HomeworkAssignment {
  id          String   @id @default(uuid())
  classId     String
  subject     String
  title       String
  description String
  attachments String[] // Storage URLs
  dueDate     DateTime
  createdAt   DateTime @default(now())
}

model MarkRecord {
  id            String         @id @default(uuid())
  studentId     String
  subject       String
  assessment    String         // e.g., "Term 1 Exam"
  marksObtained Float
  maxMarks      Float
  student       StudentProfile @relation(fields: [studentId], references: [id])
}

model AuditLog {
  id        String   @id @default(uuid())
  schoolId  String
  actorId   String
  action    String
  target    String
  payload   Json
  timestamp DateTime @default(now())
  school    School   @relation(fields: [schoolId], references: [id])
  actor     User     @relation(fields: [actorId], references: [id])

  @@index([schoolId, timestamp])
}
```

## 6. Complete Phase-Wise Development Roadmap

### Phase 0: System Core, Auth & RBAC Architecture
* **Deliverables:**
  1. Initialize Next.js App Router application with TypeScript and Tailwind CSS.
  2. Configure Prisma ORM PostgreSQL connection pool.
  3. Implement NextAuth (Auth.js) JWT session handling containing `userId`, `role`, and `schoolId`.
  4. Construct Next.js `middleware.ts` to block cross-tenant route navigation and unauthenticated API calls.
* **Exit Criteria:** Unauthenticated requests redirect to login; cross-tenant navigation returns HTTP 403 Forbidden.

### Phase 1: Multi-Tenant Setup & CSV Roster Import
* **Deliverables:**
  1. CRUD management screens for School, AcademicYear, Class, and Section entities[cite: 1].
  2. CSV import parser using `papaparse` to mass-import student and teacher rosters with server validation[cite: 1].
  3. Dashboard layouts for Admin, Teacher, Student, and Parent accounts[cite: 1].
* **Exit Criteria:** Admins can upload a class CSV roster, automatically generate active accounts, and correct duplicate records[cite: 1].

### Phase 2: Attendance Engine, Timetable & Audit Log
* **Deliverables:**
  1. Daily and period-wise attendance submit screens featuring "Mark All Present" and exception toggles[cite: 1].
  2. Database constraint enforcement on `(classId, date, period)` to safely reject duplicate submissions[cite: 1].
  3. Automatic trigger writing to `AuditLog` whenever finalized attendance is corrected[cite: 1].
  4. Interactive weekly timetable viewer for teachers and students[cite: 1].
* **Exit Criteria:** Attendance recorded safely once per session[cite: 1]; post-finalization edits create a logged audit record containing submitter ID and timestamp[cite: 1].

### Phase 3: Homework Engine & Early Years Activity Diary
* **Deliverables:**
  1. Homework creation form with rich instructions and attachment upload functionality[cite: 1].
  2. Activity Diary mode specifically for Nursery/LKG/UKG classes[cite: 1].
  3. Homework submission tracking dashboard (Assigned, Submitted, Late, Reviewed)[cite: 1].
* **Exit Criteria:** Teachers publish homework to assigned classes; linked students and parents view relevant entries instantly[cite: 1].

### Phase 4: Gradebook, Band-Specific Assessments & PDF Report Cards
* **Deliverables:**
  1. Flexible assessment evaluation schema (Numerical marks for upper classes; developmental progress indicators for Early Years)[cite: 1].
  2. Marks entry interface with client/server range validation (`marksObtained <= maxMarks`)[cite: 1].
  3. Dynamic PDF report card generator built with `@react-pdf/renderer`[cite: 1].
* **Exit Criteria:** PDF report cards render accurately; published grades are locked from further editing without admin approval[cite: 1].

### Phase 5: Parent Portal & Notification Queue
* **Deliverables:**
  1. Parent portal view filtered strictly to linked children[cite: 1].
  2. Target announcement broadcasting (School-wide, Class-wide, Individual)[cite: 1].
  3. Asynchronous job queue setup using BullMQ and Redis to process parent notifications without blocking main API routes[cite: 1].
* **Exit Criteria:** Absence alerts queue successfully without blocking web app performance[cite: 1]; parents access only verified child data[cite: 1].

## 7. Agent Validation Rules & Acceptance Tests

Before proceeding past any development phase, the Antigravity Agent must pass the following validation rules:

1. **Tenant Isolation Check:** Any database query executed without `WHERE school_id = context.schoolId` must fail or return zero records[cite: 1].
2. **Duplicate Protection Check:** Submitting attendance twice for the same class, date, and period must throw a duplicate prevention exception[cite: 1].
3. **Marks Range Validation Check:** Entering assessment marks greater than `maxMarks` must trigger validation errors on both client and server layers[cite: 1].
4. **Parent Link Privacy Check:** Direct URL parameter manipulation by a parent attempting to access another student's record must return HTTP 403 Forbidden[cite: 1].
5. **Audit Traceability Check:** Any edit to finalized attendance or published grades must generate a row in `AuditLog` storing the previous value, new value, actor ID, and timestamp[cite: 1].
